対象アプリの起動と動作確認

以下の手順に従ってアプリを起動し、現時点のアプリの動作をご自由にお試しください。

実行場所: 以下のコマンドはすべて inventory-app ディレクトリ（requirements.txt があるフォルダ）で実行してください。 Bob IDE の統合ターミナル（メニューの ターミナル → 新しいターミナル）を使うと、このフォルダで開きます。

1. Python仮想環境の作成

python -m venv venv
Windowsの方へ: python と入力してMicrosoft Storeの画面が開いてしまう場合は、 python の代わりに py をお使いください（py -m venv venv）。

2. 仮想環境の有効化

# Windows (コマンドプロンプト) の場合:
venv\Scripts\activate
# Windows (PowerShell) の場合:
venv\Scripts\Activate.ps1
# macOS/Linuxの場合:
source venv/bin/activate
PowerShellでエラーが出る場合: このシステムではスクリプトの実行が無効になっているため... と表示されたら、 同じターミナルで次を実行してから、もう一度有効化してください（そのターミナルの間だけ有効な設定です）。 
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
有効化に成功すると、プロンプトの先頭に (venv) と表示されます。

3. Python依存パッケージのインストール

pip install -r requirements.txt

4. アプリケーションの起動

python app.py

ブラウザで http://localhost:5001 にアクセスしてください。

macOSの方へ: 初回起動時に「python へのネットワーク受信接続を許可しますか？」というダイアログが表示される場合があります。 許可 を選択してください（拒否しても localhost でのアクセスは可能です）。

5. 正しく起動できたかの確認

以下の2点が確認できれば、環境構築は成功です。

① ターミナルに次のような表示が出て、入力待ちの状態になる

 * Serving Flask app 'app'
 * Debug mode: on
WARNING: This is a development server. Do not use it in a production deployment. Use a production WSGI server instead.
 * Running on all addresses (0.0.0.0)
 * Running on http://127.0.0.1:5001
 * Running on http://192.168.1.7:5001
Press CTRL+C to quit
 * Restarting with stat
 * Debugger is active!
 * Debugger PIN: 126-533-096

プロンプトが返ってこないのが正常です。この状態のままブラウザを開いてください。

赤い WARNING は異常ではありません。 「これは開発用サーバーなので本番環境では使わないでください」という案内で、ハンズオンでは問題ありません。 Debugger PIN の数字や 192.168.x.x のアドレスは、環境によって異なります。

② ブラウザのダッシュボードに、以下の数値が表示される

項目 表示される値

総在庫数 410

数値が違う場合: すでにアプリを操作して商品を追加・入出庫された場合は、上記と異なる数値になります。異常ではありませんので、そのまま進めていただいて問題ありません。

ハンズオンの流れ

今回のハンズオンでは、既存アプリに対して Bob の設定や拡張を段階的に追加していきます。

  1. 既存リポジトリから AGENTS.md を生成する
  2. コーディング規約に基づき、Rules を作成し、既存コードに適用する
  3. MCP（context7）を設定し、カスタムモードを作成してアプリに機能を追加する体験を行う
  4. コードレビュー用 Skill を作成し、そのまま Rules に基づくコードレビューを実施する

シナリオ① AGENTS.md 作成

想定時間: 10分 Mode: 🤖 Agent

目的

  • 既存リポジトリを Bob に理解させる
  • /init で AGENTS.md を自動生成し、プロジェクト理解の起点を作成する
  • プロジェクト全体とモード別のコンテキストを一度に設定する

実施手順

  1. Bob IDE で inventory-app ディレクトリをワークスペースとして開きます。
  2. Agentic Chat を Agent mode に切り替えます。
  3. チャットに次のコマンドだけを入力して実行します。
✏️ 編集してコピーできます
  1. ファイルの読み取りと書き込みの許可を求められた場合は許可します。

Bobの動作

/init はプロジェクト内の関連ファイルを読み取り、プロジェクトルートに AGENTS.md を生成します。また、.bob 配下に各 Bob モードで使用するモード別の AGENTS.md を生成します。

  • AGENTS.md: Bob がプロジェクトを理解するためのコンテキスト
  • .bob/rules-agent/AGENTS.md: Agent mode 用のコンテキスト
  • .bob/rules-plan/AGENTS.md: Plan mode 用のコンテキスト
  • .bob/rules-ask/AGENTS.md: Ask mode 用のコンテキスト

学習ポイント

  • /init 一回で、Bob が既存プロジェクトの構成や規約を把握できることを体験する
  • 生成された AGENTS.md が、新しい会話でもプロジェクトコンテキストとして利用されることを確認する

補足

  • 生成されたファイルの内容を必ず確認してください
  • AGENTS.md はプロジェクトの一部としてバージョン管理してください
  • 大きな変更後は /init を再実行してコンテキストを更新できます

オプション: Bob Shell ハンズオン

想定時間: 30分

目的

  • Bob Shell をインストールして起動する
  • インタラクティブセッションで Bob Shell に質問する
  • ワンライナーで Bob Shell を実行する

STEP1: Bob Shell のインストール

Bob Shell は Node.js 上で動作するCLIツールです。Bob IDE とは独立して、公式のインストールスクリプトでセットアップします。

前提: Node.js が必要です。 公式の要件は Node.js 24 以降です。 ターミナルで node -v を実行して確認し、コマンドが見つからない場合やバージョンが古い場合は nodejs.org から LTS 版をインストールしてください。

1. インストールスクリプトの実行

ターミナル（Windowsの場合は PowerShell）を開き、OSに合わせて次のコマンドを実行します。

# macOS/Linux の場合:
curl -fsSL https://bob.ibm.com/download/bobshell.sh | bash
# Windows (PowerShell) の場合:
powershell -c "irm -Uri https://bob.ibm.com/download/bobshell.ps1 | iex"

スクリプトは Node.js のバージョンを確認したあと、パッケージの整合性（SHA256）を検証してグローバルインストールを行います。 npm / pnpm / yarn が複数入っている場合は、どれを使うか番号で選択を求められるので npm を選んでください（npm しか無い環境では自動的に npm が選ばれます）。

選択を省略したい場合: パッケージマネージャーを引数で指定できます。 
# macOS/Linux の場合:
curl -fsSL https://bob.ibm.com/download/bobshell.sh | bash -s -- --pm npm
# Windows (PowerShell) の場合:
powershell -c "& ([scriptblock]::Create((irm -Uri https://bob.ibm.com/download/bobshell.ps1))) -pm npm"

2. インストールの確認

インストール後は新しいターミナルを開き直してから（PATHを反映させるため）、次のコマンドでバージョンを確認します。

bob --version
うまくいかない場合:
  • command not found: bob / bob は認識されません と出る場合は、ターミナルを開き直してください。それでも解決しない場合は、npm のグローバルインストール先（npm prefix -g で表示されるパスの bin 配下。Windows はそのパス直下）がPATHに含まれているか確認してください。
  • PowerShell で このシステムではスクリプトの実行が無効になっているため... と表示される場合は、このページ前半の「PowerShellでエラーが出る場合」と同じく、同じターミナルで Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass を実行してから再度お試しください。
補足: Bob IDE の設定によっては、Bob IDE 側から Bob Shell が自動インストールされる場合があります。 その場合もインストールされる中身は上記スクリプトと同じものです。すでに bob --version が通る場合は、このSTEPは飛ばして構いません。

STEP2: Bob Shell の起動

ターミナルを開き、プロジェクトディレクトリで次のコマンドを実行します。

bob

引数なしの bob はインタラクティブセッション（ターミナルUI）を起動します。bob chat と明示しても同じです。

初回起動時: IBMのライセンス条項への同意と、ブラウザでのサインイン（IBMid / SSO）を求められる場合があります。画面の案内に従って進めてください。

Bob Shell が起動したら、インタラクティブセッションで次の質問を入力します。

STEP3: API key の取得

非インタラクティブセッションでBob Shellを実行する場合（ブラウザを開けない環境やCI/CDなど）は、API key認証を使用します。

  1. Bob Web にサインインします。
  2. サブスクリプション・インスタンスを開き、API keyの管理画面に移動します。
  3. API keyを作成し、キーの種類は Inference を選択します。
  4. 表示されたAPI keyを安全な場所にコピーします。作成後はキーの値を再表示できないため、ソースコードやログに記録しないでください。

STEP4: 非インタラクティブセッションで Bob Shell を実行

取得したAPI keyを環境変数に設定します。以下はmacOS/Linuxの例です。

export BOB_API_KEY="取得したAPI key"

Windows PowerShellの場合は、次のように設定します。

$env:BOB_API_KEY="取得したAPI key"

環境変数に設定したAPI keyを使い、非インタラクティブセッションでシナリオ④で作成した /review スキルを実行します。あらかじめシナリオ④で /review スキルを作成しておいてください。

bob --prompt "/review"

このコマンドはインタラクティブセッションを開始せず、1回のプロンプトを処理して終了します。.bob/rules/ の開発標準とセキュリティ観点に基づくコードレビューが、ブラウザを開かずに実行されます。CI/CDのパイプラインに組み込めば、コミットやプルリクエストのたびに自動でレビューを走らせる、といった運用も可能です。CI/CDでは、BOB_API_KEYをCI/CDのシークレットとして登録し、ログに出力しないでください。

期待した出力が得られない場合

  • タスクは小さく分割し、こまめに依頼してください

  • .bob/custom_modes.yaml
  • .bob/skills/review/SKILL.md

の2点が意図通りか確認してください。
