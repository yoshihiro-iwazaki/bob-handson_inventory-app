# Python コーディング規約

## 1. 命名規則

- **ファイル名**：snake_case を使用
- **クラス名**：PascalCase を使用
- **関数/メソッド名**：snake_case を使用
- **変数名**：snake_case を使用
- **定数**：UPPER_SNAKE_CASE を使用
- **プライベート変数**：_snake_case を使用（アンダースコアで始める）
- 命名は説明的であること。単一文字や略語は避ける

## 2. Docstring（ドキュメント文字列）

- すべての関数とクラスに Docstring を記述すること
- 関数の Docstring には以下を含める：概要、引数（Args）、戻り値（Returns）、例外（Raises）
- クラスの Docstring には以下を含める：クラスの目的、属性（Attributes）
- 日本語で記述すること

## 3. Import の順序

以下の順序で整理し、各グループ間に空行を入れる：
1. 標準ライブラリ
2. サードパーティライブラリ
3. ローカルモジュール

## 4. コードフォーマット

- **行の長さ**：1行は最大 100 文字まで
- **インデント**：スペース 4 つを使用。タブは使用禁止
- **空行**：クラス定義の前後に 2 行、関数定義の前後に 2 行、メソッド間は 1 行
- 長い行は適切に改行し、可読性を保つこと

## 5. コメント規約

- 日本語で記述すること
- 「何を」ではなく「なぜ」を説明すること
- 自明なコードにはコメント不要
- 複数行のコメントは各行の先頭に # を付ける

## 6. 例外処理

- 具体的な例外タイプをキャッチすること。裸の except は使用禁止
- 必要に応じて raise で例外を再送出すること
- 例外情報をログに記録すること

## 7. 型ヒント

- 型ヒント（Type Hints）の使用を推奨
- typing モジュールの List、Dict、Optional などを使用すること

## 8. コードスタイル

- **リスト内包表記**：シンプルな処理のみに使用。複雑な処理は通常のループを使用
- **文字列フォーマット**：f-string を優先使用（Python 3.6+）。format() メソッドも可。% フォーマットは禁止
- **関数設計**：単一責任の原則に従うこと。1 つの関数は最大 50 行まで

## 9. 禁止事項

以下は厳格に禁止：
- グローバル変数の使用
- 可変デフォルト引数の使用（例：def func(items=[])）
- 裸の except によるすべての例外のキャッチ
- from module import * の使用

## 10. pandas 使用規約

- メソッドチェーンを優先的に使用すること
- 条件フィルタリングにはブール索引を使用すること
- 必要な列を明示的に指定すること


**参考標準**：PEP 8 -- Style Guide for Python Code(https://pep8.org/)
**注意**：本規約は強制実施基準です。すべてのコード提出前にチェックを通過する必要があります。
