# 在庫管理アプリ 要件定義書

## 1. プロジェクト概要

### 1.1 プロジェクト名
在庫管理アプリ（Inventory Management System）

### 1.2 プロジェクトの背景
中小企業における在庫管理の課題（リアルタイム把握困難、履歴追跡の煩雑さ、情報共有の非効率）を解決するため、Webベースの在庫管理アプリを構築する。

### 1.3 プロジェクトの目的
- 在庫管理業務の効率化（50%削減目標）
- リアルタイムな在庫状況の可視化
- 履歴データに基づく意思決定支援
- 将来的な機能拡張への対応

### 1.4 対象ユーザー
- **在庫管理担当者**: 入出庫処理、在庫確認
- **倉庫管理者**: 在庫監視、発注判断
- **経営層**: サマリー確認、経営判断

**想定規模**: 同時利用5〜10名、管理商品100〜1,000品目

### 1.5 開発スケジュール
- 要件定義: 2026年1月
- 設計・開発: 2026年2月〜4月
- 本番稼働: 2026年5月

## 3. 機能要件

### 3.1 ダッシュボード（F-001〜F-003）

**在庫サマリー表示**
- 総商品数、総在庫数、総在庫額、カテゴリ数を4つのカードで表示
- 色分けとアイコンで視覚的に識別

**最近の履歴表示**
- 直近5件の入出庫履歴をテーブル表示
- 入庫（緑）/出庫（赤）をバッジで区別

**クイックアクション**
- 商品追加、商品検索、履歴確認へのショートカット

### 3.2 商品管理（F-004〜F-007）

**商品一覧表示**
- ID、商品名、カテゴリ、在庫数、単価、在庫額、登録日、操作ボタン
- 在庫数10未満は赤色バッジで警告

**商品検索**
- 商品名・カテゴリで部分一致検索（大文字小文字区別なし）

**商品新規登録**
- 入力項目: 商品名（必須）、カテゴリ（必須）、初期在庫数、単価
- モーダルダイアログで入力、自動ID採番
- 初期在庫数>0の場合、入庫履歴を自動作成

**在庫更新（入庫・出庫）**
- 操作種別（入庫/出庫）と数量を入力
- 出庫時の在庫不足チェック（マイナス不可）
- 履歴への自動記録

### 3.3 履歴管理（F-008〜F-010）

**全履歴表示**
- 全入出庫履歴を日時降順で表示
- 商品名クリックで商品別履歴へ遷移

**商品別履歴表示**
- 特定商品の履歴のみ表示

**統計情報**
- 入庫回数・出庫回数の集計表示

## 4. データ設計

### 4.1 商品データ（products.csv）

| カラム名 | データ型 | 説明 |
|----------|----------|------|
| id | 整数 | 商品ID（主キー） |
| name | 文字列 | 商品名 |
| category | 文字列 | カテゴリ名 |
| quantity | 整数 | 在庫数 |
| price | 数値 | 単価（円） |
| created_at | 日時 | 登録日時 |

### 4.2 履歴データ（history.csv）

| カラム名 | データ型 | 説明 |
|----------|----------|------|
| id | 整数 | 履歴ID（主キー） |
| product_id | 整数 | 商品ID |
| product_name | 文字列 | 商品名 |
| action | 文字列 | 操作種別（入庫/出庫） |
| quantity_change | 整数 | 数量変化（±） |
| quantity_after | 整数 | 操作後在庫数 |
| timestamp | 日時 | 操作日時 |

## 5. 画面設計

| 画面名 | URL | 主要機能 |
|--------|-----|----------|
| ダッシュボード | / | サマリー表示、最近の履歴 |
| 商品管理 | /products | 一覧、検索、追加、更新 |
| 履歴管理 | /history | 全履歴、商品別履歴、統計 |

**共通レイアウト**
- ヘッダー: アプリ名、ナビゲーションメニュー
- カラースキーム: 青（プライマリ）、緑（成功/入庫）、赤（危険/出庫）、黄（警告）

---

## 6. API設計

| メソッド | エンドポイント | パラメータ |
|----------|----------------|------------|
| GET | / | - |
| GET | /products | search（任意） |
| POST | /products/add | name, category, quantity, price |
| POST | /products/<id>/update | action, quantity |
| GET | /history | product_id（任意） |

---

## 7. 非機能要件

- **性能**: 応答時間2秒以内、同時接続10ユーザー、商品数1000件まで
- **可用性**: CSVファイルの手動バックアップ
- **セキュリティ**: ローカル環境での実行想定（認証機能は将来拡張）
- **互換性**: モダンブラウザ、Python 3.12〜3.14

---

## 8. エラーハンドリング

| エラーコード | 説明 | 対処 |
|--------------|------|------|
| E-001 | 必須項目未入力 | エラーメッセージ表示 |
| E-002 | 在庫不足 | エラーメッセージ表示 |
| E-003 | ファイル読込エラー | 空リスト返却 |
| E-004 | 無効な操作 | エラーメッセージ表示 |

## 9. 制約事項

**技術的制約**
- データベース不使用（CSV形式のみ）
- 同時書き込みの排他制御なし

**機能的制約**
- ユーザー認証なし
- 商品画像管理なし
- 複数拠点管理なし

---

## 10. 用語集

| 用語 | 説明 |
|------|------|
| 在庫数 | 現在保有している商品の数量 |
| 入庫 | 商品を倉庫に入れる操作（在庫増加） |
| 出庫 | 商品を倉庫から出す操作（在庫減少） |
| 在庫額 | 在庫数×単価で算出される金額 |
